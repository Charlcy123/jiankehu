# 速记整理规范

这份规范讲的是"逐字稿 → 速记稿"这一步怎么做。读者是写稿的人和要复盘的人，他们不在现场，速记稿是他们唯一的现场。所以两条底线：**忠实**（不能让读者信了一句说话人没说的话），**好读**（读者不该被嗯嗯啊啊耗掉耐心）。

目录：
1. 删什么、留什么
2. 同音错字和专有名词
3. 说话人推断
4. 分段与小标题
5. 时间戳
6. 数字、金额、日期
7. 前后对照示例
8. 常见错误

## 1. 删什么、留什么

### 删

| 类型 | 例子 |
|------|------|
| 语气词、填充词 | 嗯、啊、呃、哦、那个、这个、就是、就是说、然后呢、对吧、你知道吧、怎么说呢 |
| 纯重复 | "我我我觉得" → "我觉得"；"这个这个方案" → "这个方案" |
| 说一半推翻的碎片 | "我们打算在三月——不对，应该是四月上线" → "我们应该是四月上线"（保留最终说法） |
| 与内容无关的过程 | 开头调设备、"能听见吗"、倒水、中途接电话、结尾寒暄 |
| 转写引擎的幻听 | 静音段出现的重复句、"请不吝点赞订阅"之类的训练数据残留、完全不搭的外语句子 |

### 留

| 类型 | 为什么留 |
|------|---------|
| 口语化但有信息的表达 | "这事儿挺悬的"比"存在不确定性"更能传达说话人的判断强度 |
| 有意的重复和强调 | 客户连说三遍"一定不要做成广告"，这个"三遍"就是信息 |
| 转折前的停顿 | 用"……"保留，"我们当然愿意合作……但预算这块确实没批下来" |
| 情绪 | 用括号标：（笑）（沉默几秒）（语气明显加重） |
| 说话人的自我修正 | 如果修正本身有意义（比如把数字说错又改口），两个都留并标 `[说话人随后更正]` |
| 提问 | 采访和会议里提问决定了回答的语境，不要删掉只留回答 |

删的原则一句话：**删掉之后读者对说话人的理解不会变，才能删。**

## 2. 同音错字和专有名词

转写引擎在这几类地方最容易错：

- **人名、品牌名、项目名**：引擎会转成常见同音词。"三联"可能变"三连"，"周刊"变"周看"。有热词表就对着改，没有的就按上下文改，改了但没把握的加 `[?]`
- **行业黑话和英文缩写**：KOL、KPI、brief、PR 稿、投放……中英混杂的地方引擎经常拆错，比如"做一个brief" 转成"做一个 be leaf"。按行业常识还原
- **数字**：一/七、四/十、十四/四十 这些引擎经常混。数字有疑问就标 `[?]`，不要凭感觉定
- **同音词**：在/再、的/地/得、做/作、像/向。这类按语法改，不用标注

原则：**改错字不算改原话。** 但改了之后意思变了的（比如"不行"和"不幸"），一定要回逐字稿确认，确认不了就标存疑。

## 3. 说话人推断

Whisper 系列引擎不分说话人，速记稿里的说话人标注是你推断的。推断依据按可靠程度排：

1. **用户直接告诉你的**（"录音里是我和客户王总"）
2. **称呼和自称**："王总您看"、"我们三联这边"、"你们品牌方"
3. **角色行为**：提问的是采访者，回答的是受访者；介绍公司的是乙方，提需求的是甲方
4. **话题连续性**：一个人回答问题时通常不会自己问自己下一个问题
5. **口头禅**：某个人反复用"其实呢"，另一个人反复用"OK"

推断出来的说话人，在"基本信息"表里标"（推断）"，在"存疑"一节里写依据。**推断不出来就用"说话人A/B"**，不要为了稿子好看硬安名字——标错说话人比不标更糟，读者会把甲方的顾虑当成乙方的承诺。

多人会议（四人以上）而且分不清的，退一步：只区分"客户方"和"我方"，或者"主讲人"和"提问者"。

## 4. 分段与小标题

- 按**话题**切小节，不按时间。一个小时的会可能只有四五个话题，每个话题是一节
- 小标题写**内容**，不写序号："关于第二季度投放节奏的分歧"，而不是"第二部分"
- 一个人连续说超过 200 字，按意思切成几段。只在第一段前标说话人和时间戳
- 话题来回跳的（客户会议常见），按话题归拢是可以的，但要在时间戳上如实反映——读者看到 [12:30] 后面跟着 [41:05]，就知道这是归拢过的
- 归拢时不能改变因果：如果客户是先否定了方案 A 才说想要方案 B，速记里不能把 B 放到 A 前面

## 5. 时间戳

- 格式 `[mm:ss]`，超过一小时 `[h:mm:ss]`
- 取逐字稿里该段发言的**起始**时间
- 要点摘要、可引用原话、存疑清单里每条都要有时间戳。速记稿的价值一半在"能回查"
- 用户提供的转写文本如果没有时间戳，速记稿就不带，但要在基本信息里注明"原文本无时间戳"

## 6. 数字、金额、日期

这是速记稿里出错代价最高的地方。规则：

- 逐字稿怎么说就怎么写，用阿拉伯数字："三百万" → "300 万"
- 模糊说法保留模糊："大概两三百万"不能写成"250 万"
- 相对时间保留相对："下个月"不要换算成具体月份（你不确定录音是哪天录的）；如果用户告诉了录音日期，可以在括号里加注："下个月（即 10 月）"
- 引擎转出来的数字有疑问（前后文对不上、大得离谱）标 `[?]`
- 涉及金额、比例、截止日期的句子，放进"可引用原话"里保留原句，方便读者核

## 7. 前后对照示例

### 例一：去噪

逐字稿：
```
[03:12] 嗯我觉得就是说这个这个方向呢其实我们内部之前也讨论过，就是那个，怎么说呢，我们其实不太想做成那种很硬的广告，就是那种一看就是广告的东西，对吧，我们更希望它是一个，嗯，有内容的东西。
```

速记：
```
**王总（客户，推断）** [03:12]
这个方向我们内部之前也讨论过。我们不太想做成那种很硬的、一看就是广告的东西，更希望它是一个有内容的东西。
```

删了：嗯、就是说、这个这个、呢、其实、就是那个、怎么说呢、对吧、嗯。留了："很硬的""一看就是广告的东西"——这是客户自己的说法，比"软性植入"更准确地反映他的态度。

### 例二：不补不美化

逐字稿：
```
[15:40] 预算……这个我得回去问一下，我不能现在给你一个数，但是肯定不会是，嗯，不会是你们上次那个报价那么高。
```

错误整理（补了没说的话）：
```
预算需要回去确认，目前暂时无法给出具体数字，但预计会低于上次报价，可能在上次报价的七到八折之间。
```
"七到八折"是编的。"预计"也不是他的语气，他说的是"肯定不会"。

正确整理：
```
**王总** [15:40]
预算……我得回去问一下，现在不能给你一个数，但肯定不会是你们上次那个报价那么高。
```

### 例三：转写幻听

逐字稿：
```
[42:10] 好那我们今天就先到这里
[42:15] 谢谢大家
[42:15] 谢谢大家
[42:15] 谢谢大家
[42:15] 谢谢大家
[42:20] 字幕由 Amara.org 社区提供
```

处理：正文只保留到"谢谢大家"一句。存疑清单里写：`[42:15-42:20] 引擎在结尾静音段产生重复和无关文字，已删除`。

### 例四：可引用原话

正确（只删语气词）：
```
> "我们不太想做成那种很硬的、一看就是广告的东西。" ——王总 [03:12]
```

错误（改了词）：
```
> "我们不希望内容广告化。" ——王总 [03:12]
```
第二句不是他说的。写稿的人如果直接引用，就是在替客户造句。

## 8. 常见错误

- **把速记写成了纪要。** 纪要是结论，速记是过程。速记正文里应该看得到对话是怎么推进的
- **摘要里出现正文没有的信息。** 摘要是从正文里提炼的，不能在摘要里加自己的理解
- **为了"完整"硬填听不清的地方。** 一个 `[听不清]` 比一句编出来的话诚实一百倍
- **说话人一律标了名字但没说哪些是推断的。** 读者不知道该不该信
- **可引用原话选的是"好看"的句子而不是"有用"的句子。** 选带具体信息（数字、案例、明确态度）的，不选空泛的漂亮话
- **存疑清单是空的。** 一小时的录音不可能没有一处存疑。空的存疑清单本身就可疑
