# 录音转速记

把一段录音变成"人能直接拿来用"的速记稿。核心不是转文字（机器都会），而是**转出来之后怎么整理**：谁说的、说了什么、哪些是原话可以引用、哪些地方没听清要标出来。

速记稿的读者是写稿的人、写提案的人、要复盘会议的人。他们不在现场，只能靠这份稿子还原现场，所以稿子要**忠实**（不编、不补、不美化），同时**好读**（去掉嗯啊、分好段、标好人）。

---

## 流程总览

```
输入 → ① 判断输入类型 → ② 转写（脚本）→ ③ 整理（你来做）→ ④ 自检 → 输出两个文件
```

- `<原文件名>-逐字稿.txt`：机器原始转写，带时间戳，用于核对，不做任何加工
- `<原文件名>-速记.md`：整理后的速记稿，按 `assets/速记模板.md` 的结构

两个文件都放在输入文件同目录（或用户指定的目录）。逐字稿一定要留着，速记稿里任何一句话有疑问，读者都要能回逐字稿对时间戳找原音。

---

## ① 判断输入类型

| 用户给的是 | 怎么办 |
|-----------|--------|
| 音频/视频文件（m4a、mp3、wav、mp4、amr、flac、ogg、opus、wma、mov） | 走 ② 转写 |
| 已有转写文本（讯飞、飞书妙记、腾讯会议、剪映导出的 txt/srt/docx） | 跳过 ②，直接 ③ 整理。把用户的文本原样复制一份作为 `-逐字稿.txt`（不改一个字）。先看一眼文本有没有时间戳和说话人标记，有就保留；时长按最后一个时间戳推断，基本信息里注明"按最后时间戳推断"；没有时间戳就注明"原文本无时间戳" |
| 多个文件 | 逐个转写，按文件名或用户说的顺序合并成一份速记，正文里用小节标出来自哪个文件 |
| 只有一段贴进来的口语文字 | 直接 ③ 整理，输出不用带时间戳 |

开始前如果用户没说，**自己推断**这三件事，不要停下来问（推断结果写进速记稿的"基本信息"里，用户不满意会改）：

1. **场景**：采访 / 客户会议 / 内部会议 / 讲座或分享 / 播客或对谈。从文件名、用户的话、转写内容里判断。场景决定整理的侧重（见 ③）
2. **说话人数**：转写引擎不做说话人分离，要从内容推断——提问的和回答的、主持的和分享的、口头禅和称呼（"您""咱们""我们这边"）。推断不出来就统一标"说话人A/B/C"，并在存疑清单里请用户确认
3. **专有名词**：品牌名、人名、项目名、行业黑话。用户提过的、文件名里有的，先收集起来作为热词传给转写脚本，转写准确率会明显提高

---

## ② 转写

用 `scripts/transcribe.py`，不要自己重新写转写代码。

```bash
# 第一次用先检查环境（依赖装没装、模型能不能下载）
python3 scripts/transcribe.py --check

# 转写。热词用逗号分隔，是你在 ① 收集的专有名词
python3 scripts/transcribe.py 录音.m4a --hotwords "三联,生活周刊,张三,某某品牌" --out ./
```

脚本会输出三个文件：`<名>.segments.json`（结构化）、`<名>.txt`（每段带 `[mm:ss]`）、`<名>.srt`。把 `.txt` 直接复制为 `<原文件名>-逐字稿.txt`。

**引擎选择**：脚本默认 `--engine auto`，优先本机 faster-whisper（免费、离线、中文效果好），本机跑不了就依次尝试环境变量里配置了 key 的云端引擎。模型大小按时长自动选：短音频用 small 试跑快，一小时以上用 medium 或 large-v3 保证准确。用户要求快出结果就 `--model small`，要求准就 `--model large-v3`。引擎细节、装不上怎么办、方言和中英混杂怎么处理，见 `references/engines.md`。

**转写完先扫一眼逐字稿**，做三个判断再开始整理：

- 有没有大段乱码、重复句（Whisper 在静音段会"幻听"出重复文字）——有就标记，整理时删掉，并在存疑清单里注明时间段
- 中英混杂、方言、多人抢话的段落——这些是错误高发区，整理时逐句多想一下
- 音质差到几乎没内容——直接告诉用户，不要硬整理出一份看起来像样的稿子

## ③ 整理（这一步决定稿子好不好用）

按 `assets/速记模板.md` 的结构写速记稿。整理规范的完整版和前后对照例子在 `references/整理规范.md`，第一次做之前读一遍。想看一份完整成品长什么样，对照 `assets/示例-逐字稿.txt` 和 `assets/示例-速记.md`。这里是最重要的几条：

### 忠实第一

- **不编。** 听不清就写 `[听不清 12:34]`，不猜。人名、数字、金额、日期、比例，逐字稿怎么写就怎么写，不确定就加 `[?]`。一个编出来的数字会毁掉整份稿子的可信度
- **不补。** 说话人没说的逻辑连接、没说的结论，不要替他补上。速记不是纪要，不要"帮他说清楚"
- **不美化。** 保留说话人的用词习惯和语气。他说"这事儿挺悬的"，不要改成"该事项存在较大不确定性"

### 去噪但不去味

删掉的：语气词（嗯、啊、呃、那个、就是说、对吧、你知道吧）、纯重复（"我我我觉得"）、说了一半又推翻的碎片、录音开头结尾的寒暄和设备调试。

留下的：口语化但有信息的表达、停顿后的转折、笑声或情绪（用 `（笑）` 标注）、说话人的强调和重复（重复三遍"一定要"是有意义的）。

### 分段和标人

- 按**话题**分小节，不按时间平均切。每个小节一个小标题，小标题用内容概括，不用"第一部分"
- 每个发言前标说话人和时间戳：`**张三** [03:12]`。时间戳取该段在逐字稿里的起始时间
- 一个人连续说很长，按意思切成几段，只在第一段标时间戳

### 按场景调侧重

| 场景 | 速记稿侧重 |
|------|-----------|
| 采访 | 受访者原话尽量完整保留，"金句"部分要多，提问可以精简 |
| 客户会议 | 客户的需求、顾虑、否定过的方向要一字不差；"待办/决定"部分要清楚谁承诺了什么 |
| 内部会议 | 决定和待办优先，讨论过程可以压缩 |
| 讲座/分享 | 按讲者的逻辑分小节，保留案例和数据，Q&A 单独一节 |
| 播客/对谈 | 观点交锋的地方保留双方原话，不要只留一方 |

### 金句/可引用原话

单独列出 5-15 句可以直接引用的原话。选的标准：一句话能代表说话人的观点或态度、有画面感、有具体数字或案例。这一节是给写稿的人用的，每句都要带时间戳和说话人，**必须是逐字稿里的原句**（可以删语气词，不能改词）。

---

## ④ 自检

输出前对着这几条过一遍，过不了就回去改：

1. 速记稿里的每一个数字、人名、金额，能在逐字稿里找到对应吗？
2. 有没有 `[听不清]` 该标没标的地方——你不确定但写得很肯定的句子？
3. "金句"那一节里的每一句，是原话吗？
4. 说话人标错会让读者完全误解，说话人推断没把握的地方，存疑清单里写了吗？
5. 待办/决定那一节，每条都有"谁"吗？没有明确责任人的，写"（未明确责任人）"，不要猜

自检完，用两三句话告诉用户：转写用了什么引擎和模型（用户自带文本的就说明没跑转写）、总时长、说话人怎么标的、哪几处最需要他核对。不要把速记稿内容在对话里再复述一遍。

## 文件太大传不上来

claude.ai 网页端单个文件上限约 30MB，一小时的 m4a 录音通常就超了。按用户所处环境给建议：

- **用户在本机的 Claude Code / 桌面版里**：没有上传这一步，直接读硬盘上的文件，什么都不用做
- **用户只能走网页上传**：让他先在本机跑一次压缩，再把小文件传上来。语音转写只要 16kHz 单声道，压完一小时约 12-15MB：
  ```bash
  python3 scripts/shrink.py 录音.m4a            # 得到 录音.shrunk.ogg；超过 28MB 会自动切成 录音.part01.ogg、part02...
  ```
  切了段的，让用户把所有 `.partNN.ogg` 和 `.parts.json` 一起传上来。`transcribe.py` 会自动按 `.parts.json` 里的偏移量校正每段的时间戳，几段逐字稿首尾相接即可，速记稿当一个文件整理
- **用户把文件放在 Google Drive 或网盘**：有 Drive 连接器就直接下载到本地再转写；网盘分享链接下载不了的，退回上一条
- **用户已经用手机 App 或讯飞转成了文字**：文字随便多长都传得上，直接走整理

用户手头没有 ffmpeg 也没关系，`shrink.py` 会用 faster-whisper 自带的 PyAV 解码编码。用户连 Python 都没有的，最省事的办法是手机上用剪映或系统录音机导出为"低质量/语音"格式再传。

## 常见状况

- **用户只想要摘要，不要全文**：还是先出完整速记稿，摘要就是速记稿的第一节，让用户自己决定看多少。不要只出摘要——回不去原话的摘要没法核实
- **用户说"帮我整理成文章"**：那是另一件事。先出速记稿，再问要不要基于速记稿写稿。速记稿是原料，稿子是成品，混在一起两边都做不好
- **录音两三个小时**：转写会慢（本机 medium 模型大约 1/3 到 1/2 实时），提前告诉用户，用后台运行。整理时更要按话题分小节，摘要控制在 15 条以内
- **转写引擎装不上也没有 API key**：把情况说清楚，建议用户用手机自带的录音转文字、讯飞听见或飞书妙记先转成文本再丢进来，你负责 ③ 整理。整理才是这个 skill 的核心价值，不要因为转不了写就卡住
